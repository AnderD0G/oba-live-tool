# 电脑与手机主播台控制

用户要求在现有主播台补齐三项控制：本地翻译后手动 DeepSeek 复译、iPhone/小米机位切换、豆包说话时联动 TK 麦克风。沿用当前 Mac 分支和账号绑定的手机入口，不另建产品。

## 翻译

Chrome 本地/网页翻译仍为默认渠道；单条评论随时可点击 DeepSeek，只翻译、消耗现有额度、不发送回复。失败或不明确时保留有效本地译文，显示不同原因。账号提及、数字、含义不明文本可保留原文，不硬编含义。保留有效 AI 结果，旧失败/中断快照不能覆盖它。手机与电脑一致，手机不会取得模型密钥。

## 机位与小米控制

实际 OBS 当前有两个独立场景「iPhone机位」「小米4K机位」。增加 scene 模式，切换节目场景后读取实际场景核对，不动来源裁剪/镜像/音频。旧同场景来源模式保持兼容。切机位与停止相机独立，切 iPhone 不停止小米。

小米控制接口为用户提供的局域网地址。文档和健康检查公开，其余请求由 OBA 后端携带私有令牌；手机仅访问 OBA 自己的账号绑定入口，不接触长期令牌。提供状态、手动启停、小预览、变焦、点选对焦与连续自动对焦。准确处理 offline/unknown/available=false、applied、saved=false；超时不当作停止成功，不自动重启。只在新鲜操作预览上选点，4K 主视频沿原中继进入 OBS。

2026-10-16 初次只读检查报告手机离线；用户随后提供无线配对信息并完成重新配对。实机开启后 state=capturing、镜头 available=true；原倍率 2.0 写入并保存、新鲜 JPEG、中心选点对焦、恢复连续自动对焦均取得真实成功回执。OBS 两个场景切换与回读通过，小米截图已有画面，iPhone 来源当前黑屏，需恢复手机相机信号。测试后节目场景恢复到原 iPhone 场景。

## 音频

用户选择简单固定热键联动，并明确首次验证通过后日常默认成功，不逐次 Computer Use/REA 或人工确认。Mac 使用已设置 Control+Option+M，开始豆包录音前发一次，结束/取消且释放录音后发一次恢复；两端共用同一协调器及拥有者，不允许重复点击或跨行抢占。

以 TK 起始开麦为使用约定；内部状态代表已发送动作的预期路由，不能称为读取到真实静音状态。真实发送失败或结果不确定时停止自动重试，保留中文草稿并提供一次重新对齐入口。无需反复核对日常操作。Windows 暂沿原语音行为，Mac 原生助手不在 Windows 执行。

## 验收

先覆盖状态/并发/失败/过期快照的定向回归；完成后统一类型检查、项目测试、Mac 打包与隔离应用验证，最后一次本机热键及机位实测。测试不公开发送，不开播，不把模拟录音当作物理麦克风证明。私有配置、用户数据和生成包不提交 Git。验证完成后提交推送 feat/mac-desktop 并合入 develop。
