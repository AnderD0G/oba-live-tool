# 小米相机与双机位控制

主播台把「OBS 机位切换」和「小米相机设备控制」分开。

- 「小米4K / iPhone」切换 OBS 的对应机位。切到 iPhone 不会关闭小米相机。
- 「开启小米相机」向相机服务发送明确的手动开启请求；已运行时复用。
- 「停止小米相机」会停止采集和中继，小米画面会中断。关闭主播台、关闭操作预览、退出 OBA 都不会自动停止相机。

首次在电脑主播台展开「相机服务连接」，填写私网服务地址和单独提供的 Bearer 密钥，再点「安全保存连接」。默认地址为 `http://192.168.1.5:18765`。密钥输入框留空会保留已有密钥；后台只返回「密钥已保存」状态。手机主播台可以查询和操作，不能修改服务地址或密钥。

本机配置位于 OBA 用户数据目录下的 `private/xiaomi-camera.json`，格式为 `{"version":1,"baseUrl":"http://192.168.1.5:18765","token":"单独配置"}`。Mac 上专用目录权限为 `0700`、文件为 `0600`，不留含密钥的备份；Windows 使用对应用户 AppData 中的私有目录。配置、凭据和预览图像不应提交到仓库。

「刷新状态」只读，不会开始拍摄。`off` 表示已核验关闭；`ready` 表示服务就绪；`capturing` 表示已有视频消费者。`offline` 或 `unknown` 表示无法确认，不能据此认为相机已停止。就绪或已有消费者也不保证帧率和画质，实际输出仍需观察。

镜头控制遵循服务真实结果：`available=false` 时显示不可用；写入必须收到 `success=true` 且 `applied=true` 才视为已接受。倍率的 `saved=false` 只表示当前倍率已应用、下次启动倍率未保存。保存结果缺失时显示未确认。对焦提交和恢复自动对焦都不保证主体已经清晰。

电脑与手机都提供无级变焦滑杆，支持小数倍率，步长为 0.01；也可以输入精确倍率。拖动时合并快速变化的目标，正在发送时只保留最后一个目标，避免松手后继续执行一串旧倍率。打开操作预览后可以查看取景变化；旧图保留显示，但取景改变后必须取得新鲜图像才能再次点按对焦。

点按后预览保持显示，并在选点处画出对焦框。黄色表示提交或等待设备，绿色表示手机返回 `focused`，红色表示未合焦、失败或超时；取消或未确认会单独说明。提交成功不会直接显示合焦成功。变焦、相机启停或关闭预览会清除旧的选点标记。

操作预览是小型 JPEG，不暴露内部原始视频端口。按相机 LAN API 1.2.0，电脑与手机都默认关闭预览，用户开启且页面可见时，以目标 30 帧/秒串行获取并解码图像；请求或解码较慢时等待，实际帧率以界面和设备网络状况为准。镜头设置以独立约 500ms 节拍串行查询，不逐帧探测手机。对焦成功、失败或超时都保持预览循环。

关闭、隐藏页面或退出时停止取图，取消本调用方尚未完成的图片读取并清除画面与选点；迟到响应不能重新打开预览。另一端可以继续预览，关闭预览不会停止相机或 OBS 主视频。API 服务在所有调用方约 3 秒不取图后自行结束额外预览解码；查询状态和设置不会保活预览解码器。

图像及服务器端选点凭据总有效期最多两秒，包括服务报告的帧龄和请求耗时。高帧率预览在此期限内有界保留最多 256 个选点凭据，避免另一端新帧将仍有效的画面过早挤掉。过期图像不能选点；已经提交的对焦会继续有界读取结果。变焦后先查询镜头设置，等实际 `observed_zoom` 与目标倍率接近，再获取新的预览进行点按对焦；点击图像留白不会发送对焦。

后台只访问固定白名单路径，地址必须为私网 IPv4 HTTP/HTTPS 根地址；不支持外部域名、凭据 URL、路径和查询参数。Bearer 只放请求头，不跟随重定向。镜头写入为单任务、至少间隔 200ms；滑杆只保留最新目标，重复点击不会积累成一串延迟操作。

网络超时或服务错误会显示「结果未确认」，不会自动重试、自动停止或报告已经关闭。先刷新相机状态和设置，再决定下一步。启停请求最多等待 180 秒，其余请求最多 30 秒。

开发验证（不连接真实相机）：

```sh
node node_modules/tsx/dist/cli.mjs --test tests/xiaomiCamera*.test.ts
node node_modules/typescript/bin/tsc --noEmit
```

定向用例覆盖参数/私网边界、HTTP 重定向与响应上限、超时、写入互斥和限频、稀疏离线状态、密钥脱敏、私有配置、实际/保存 ACK，以及预览鲜度和图像坐标。真实手机、镜头及 OBS 输出仍需单独验收。
