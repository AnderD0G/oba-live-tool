# 双机位独立录像与章节打点

在助播台「双路独立录像」点击「开始两路录像」。iPhone 和小米各自保存一个视频，切换节目画面时两路继续录制，不依赖是否正在采集直播评论，也不会开始直播。

在「章节标题」填写“补货”“观众问题”等备注，然后点击「打点当前机位」。正在显示 iPhone 时只给 iPhone 文件添加章节；正在显示小米时只给小米文件添加章节。未填写标题则自动编号。手机助播台也可以查看状态并打点。

录像中，`⌘⇧M`（Windows 为 `Ctrl⇧M`）也会给当前实际节目机位打点，OBS 在前台时同样可用。OBA 需要保持运行。原来的打点按钮和 `assistant_segment_toggle` 接口均已改为添加录像章节；没有独立录像时会提示先开始录像。旧片段历史保留查看。

点击「停止两路录像」正常结束文件。视频中的章节是最终位置，界面和 CSV 中的时间是提交前读取的近似时间，可能相差数帧。不要只看提示就删除原始录像。章节索引 CSV 与录像记录 JSON 路径会显示在面板里，包含机位、视频文件、标题和提交状态。

小米关闭时，仍在录制的 iPhone 可以继续打点。若当前节目对应的录像没有启动、文件发生变化、OBS 连接断开或机位无法唯一确认，操作会显示未确认或拒绝写章，避免写到另一机位。出现未确认结果时先刷新核对，不会自动补发章节。

## OBS 准备

需要 OBS 32 或更高版本与 Source Record。每个原始相机来源配置一个启用的 `source_record_filter`：

| 机位 | 唯一滤镜名称 |
| --- | --- |
| iPhone | `OBA 独立录像 · iPhone` |
| 小米 | `OBA 独立录像 · 小米4K` |

两路使用 Hybrid MOV 或 Hybrid MP4，关闭自动分段，初始录制模式为 None（0），不开启推流或回放缓冲。保存目录分别放在 iPhone 和小米子目录中。OBA 读取现有配置，不会自动安装插件、创建来源或改动全局音频和机位布局。

录制使用来源自身分辨率；“小米4K”这个名称本身不证明文件达到 4K，应以实际文件属性为准。音轨使用 OBS 中已配置的输入，TK 的麦克风路由与 OBS 录制音轨分别由各自的设置决定。

OBS 崩溃时，视频可能可以恢复，但尚未正常结束文件的章节不保证保留。OBA 会先保存打点意图和文件位置，保留未确认状态供核对。重启 OBA 后不会据旧记录擅自停止正在由 OBS 控制的外部录像。

参考：[OBS 章节与封装说明](https://obsproject.com/kb/hybrid-mp4)、[Source Record 作者项目](https://github.com/exeldro/obs-source-record)。
