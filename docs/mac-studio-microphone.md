# Mac 直播麦克风控制

OBA 通过本机 `http://127.0.0.1:18766` 麦克风接口控制 TikTok LIVE Studio 的输入静音。主播麦克风可以同时作为 TK Studio 直播输入和豆包识别输入；控制只改变 TK Studio 的收音，不禁用物理设备，不改变系统默认麦克风，也不依赖 OBS 或虚拟声卡。

## 使用

1. 打开 TK Studio 和本机麦克风接口服务，在 OBA 助播台点击“检查连接”，查看接口返回的实际开麦或静音状态。此控制无需 OBA 的 Mac 键盘或辅助功能权限。
2. 在桌面或手机点击“使用电脑麦克风”。OBA 先明确设置 TK Studio 静音，接口确认成功后才开始豆包识别。
3. 结束或取消录音后，OBA 恢复录音前的静音状态。录音前已经静音时仍保持静音。识别文字只填入中文草稿，翻译和发送由你主动操作。

桌面、手机共用一个录音 owner 和麦克风串行边界，录音期间不能单独切换。备用“切换直播麦克风”通过接口执行一次手动切换，并显示接口确认的结果，不改变后续录音恢复原状态的行为。正常使用无需逐次确认，不依赖 CUA 或 REA 读取界面，也不需要预设最初开麦。

操作超时或接口未确认结果时，OBA 不自动重试、不自动退回热键。结束录音后可点击“重新读取麦克风状态”读取实际状态并恢复联动；活动录音期间不能重置联动。豆包已成功识别但恢复麦克风失败时，识别文字仍保留，并单独提示恢复未确认。

首次开播验收应确认观众没有通过摄像头麦克风或其他音频来源听到中文。OBS 可以只负责画面。手机机位和麦克风控制不依赖评论采集，仅在本次手机入口有效期间可用。

## 接口与构建

状态使用 `GET /v1/mic`，联动使用幂等 `PUT /v1/mic` 的布尔 `muted` 目标，备用切换使用 `POST /v1/mic/toggle`。OBA 固定连接本机端口，不接受页面指定地址、不跟随重定向；写入须确认返回码及目标状态，单次请求失败不会自动重复。Windows 语音输入保留原有行为，不主动调用此 Mac 本机接口。

旧版固定 **Control + Option + M** 的原生辅助程序仍随 `pnpm build:mac` 编译打包，供兼容与测试保留；日常控制入口使用 API，不自动调用辅助程序。Windows 构建不增加 Mac 二进制依赖。设备配置和凭证均保留在本机，不提交到仓库。
